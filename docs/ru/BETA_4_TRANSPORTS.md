# MBox beta 4 — UDP и архитектура транспорта

[English](../BETA_4_TRANSPORTS.md) · [Заметки beta 4](BETA_4_RELEASE_NOTES.md)

**Статус: экспериментальная разработка, не сертифицированный VPN для production.** Опубликованная beta 3 и локальная ветка beta 4 — разные сборки. То, что QUIC работает в debug APK, ещё не означает, что он попал в подписанную release-сборку.

## Зачем два внешних транспорта

MBox передаёт пользовательские TCP-потоки, а в разрабатываемой beta 4 — также UDP-датаграммы. Виртуальный интерфейс Android, зашифрованная Noise-сессия MBox и *внешний транспорт* до сервера — разные уровни.

### HTTPS через промежуточный веб-хостинг

```text
Приложения (TCP / UDP)
  -> Android VpnService / TUN -> HEV / клиент MBox
  -> зашифрованные MBox-фреймы + надёжный протокол HTTP-запросов
  -> Chromium Cronet HTTPS (обычно HTTP/2 поверх TLS/TCP)
  -> доступный веб-фронтенд на shared hosting + FastCGI
  -> MBox origin на VPS -> настроенный выход (например, sing-box)
```

UDP приложений упаковывается **в датаграммные фреймы внутри туннеля MBox**, а сам туннель передаётся по HTTPS/TCP. То есть это **UDP-over-HTTPS/TCP**, а не нативный UDP на участке от оператора до веб-фронтенда. Потеря TCP-пакета может задержать последующие данные (head-of-line blocking). Поэтому задержки в играх, звонках и других приложениях реального времени могут быть выше. При ограниченном доступе сам веб-хостинг должен быть достижим: универсальный обход белых списков не гарантируется.

### Прямой нативный QUIC / HTTP/3

```text
Приложения (TCP / UDP)
  -> Android VpnService / TUN -> HEV / клиент MBox
  -> Noise-зашифрованные MBox-фреймы в HTTP/3 streams
  -> прямой QUIC поверх UDP -> native QUIC gateway на VPS
  -> локальный MBox origin -> настроенный выход
```

Этот путь **не использует FastCGI на shared hosting**. Снаружи — настоящий UDP/QUIC. Но в реализации сейчас используются **HTTP/3 streams, а не QUIC DATAGRAM**, поэтому нельзя выдавать её за прямую сквозную передачу независимых UDP-датаграмм. QUIC не сработает там, где заблокирован UDP до VPS.

## Режим Auto на Android

Auto выбирает транспорт при подключении или переподключении: сначала пробует QUIC, при отказе переходит на HTTPS. В полевых испытаниях разработчика на Wi-Fi выбирался QUIC, а при переключении на мобильную сеть с действующими ограничениями происходил реконнект через HTTPS. После возврата на Wi-Fi наблюдался QUIC. Это **переключение между соединениями**, а не одновременная балансировка потоков, объединение каналов или бесшовная миграция открытых соединений. При реконнекте пользовательские потоки могут обрываться.

Для диагностики сохраняется ручной выбор HTTPS и QUIC.

## Шифрование, маскировка и наблюдаемость

MBox использует Noise `NKpsk0` для аутентификации и шифрования сессии. Внешние HTTPS и QUIC дополнительно защищены TLS. Для HTTPS используется Chromium-derived стек Cronet. Это снижает очевидность Go TLS/HTTP fingerprint, но **не доказывает неотличимость от Chrome/Firefox** и не гарантирует устойчивость ко всем DPI. Провайдер по-прежнему видит IP назначения, размеры пакетов, интервалы и тип внешнего транспорта. Даже работающий cover сам по себе не доказывает отсутствие утечек.

## Известные ограничения

- Нет QUIC DATAGRAM, multipath, объединения нескольких путей и бесшовного продолжения открытых потоков после смены транспорта.
- UDP-over-HTTPS/TCP может давать существенную задержку; поведение зависит от веб-посредника.
- Ещё нет полного подтверждения отсутствия DNS/IPv4/IPv6 утечек захватом трафика на физическом интерфейсе, длительных многопользовательских испытаний и независимого аудита.
- Нужна схема обновления сертификата QUIC: срок действия используемого лабораторного сертификата, по имеющимся данным, заканчивается **07.12.2026**.
- Native QUIC и Auto испытаны в **debug APK**; до релиза необходимо проверить оба пути в подписанной release-сборке. Сейчас адрес конкретного QUIC-шлюза и публичный сертификат вшиваются в **debug assets**. Для общего релиза нужны параметры конкретного пользователя через профиль/provisioning или другой проверенный способ доставки, а не случайно опубликованный личный endpoint разработчика.
- Совместимость с предыдущими экспериментальными бетами не гарантируется.
