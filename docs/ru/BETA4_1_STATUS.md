# MBox 1.0.0-beta.4.1 — фактический статус исходников и приёмки

[English](../BETA4_1_STATUS.md) · [Тестирование](TESTING.md) · [Чек-лист](../../RELEASE_CHECKLIST.ru.md)

**Кандидат, автоматически не опубликован.** Основа — `v1.0.0-beta.4`; wire protocol и формат `mbox://` не менялись. Перед выпуском владелец должен проверить именно итоговый APK с production-подписью и посчитать его действительный SHA-256. Для Noise framePing обновлять сервер не нужно; ротация сертификатов — отдельная работа администратора.

## Подтверждённые проблемы кода и исправления

- В beta.4 Android выставлял CONNECTED после запуска локального SOCKS и ждал завершения Go core. Умерший QUIC gateway мог остаться незамеченным, если core продолжал работать.
- Сервер beta.4 уже возвращает существующий `framePing` внутри Noise. beta.4.1 использует случайный nonce 16 байт, подтверждение ответа и таймаут 10 с без изменения wire format.
- Проверки Go core — **каждые 30 с при активности, 90 с без активных потоков**, с jitter до 30%. После разблокировки/выхода из Doze запрашивается дополнительная проверка. На Android это не гарантия постоянного расхода батареи или восстановления строго за 30 секунд.
- Android показывает CONNECTING/VERIFYING/CONNECTED/RECOVERING, отдельно наблюдает QUIC gateway и HEV и обычно сохраняет full-route TUN при восстановлении транспорта.

## Собранные подтверждения

| Действие | Результат | Ограничение |
|---|---|---|
| Go client/server `go test -race` на Arch | Разработчик сообщил об успешном прохождении | Точный итоговый коммит ещё не проверен GitHub CI |
| Native QUIC `go vet` и `go test -race` | Пройдено по присланному логу | Не заменяет тестов реальной сети |
| Python первоначального патча | 114 пройдено, 1 тест упал из-за строгого сравнения пробелов | Исправление теста предоставлено, но итоговый зелёный вывод не приложен |
| ARM64 бинарники Go core и native QUIC | Собраны | Нужна сборка APK именно из финального коммита |
| Android debug APK | Разработчик сообщил об успешной сборке | Итоговый production-signed APK не прошёл отдельную приёмку |
| Подключение, простой, смена сети, полная потеря сети, Auto | Разработчик сообщил о прохождении 5/5 | Продолжительность, условия, тип подписи и логи не зафиксированы |

## Ещё не подтверждено

- Физическая причина исходного зависания (NAT, Doze, потеря пакетов, gateway). Ошибка supervisor доказана кодом; причина конкретного полевого случая — нет.
- Имитация живого, но зависшего QUIC; принудительная смерть gateway/core/HEV; блокировка QUIC при доступном HTTPS; отказ обоих путей; Stop во время recovery; гонки callbacks; soak 24–72 ч.
- Физический захват IPv4/IPv6/DNS/TCP/UDP в режимах Always-on и Android Lockdown, включая полную смерть процесса.
- Сравнение fingerprint с браузером и анализ frontend→origin; RTT/jitter, throughput, батарея.
- Проверка обновления и основных сценариев на **точно том APK с production-подписью**, который пойдёт пользователям; миграция CA и ротация TLS на VPS.

**P0 «нет утечек» пока открыт.** Always-on помогает удерживать VPN; системную блокировку подключения без VPN обеспечивает именно Android Lockdown. Независимый аудит или универсальную невидимость заявлять нельзя.
