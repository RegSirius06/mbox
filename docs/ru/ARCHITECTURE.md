# Архитектура MBox — 1.0.0-beta.4.4

[English](../ARCHITECTURE.md) · [Подписки](MBOX_SUBSCRIPTIONS.md) · [DATAGRAM](BETA44_DATAGRAM_EXPERIMENT.md) · [Безопасность](SECURITY.md)

```text
Приложения -> Android VpnService/TUN -> HEV -> Go core / Noise / MUX
                                                  |
               +--> QUIC/HTTP3/UDP ---------------+--> VPS native QUIC gateway --> origin -----+
               |                                  |                                           |
               +--> HTTPS/Cronet/TCP -------------+--> shared-host FastCGI -----> origin -----+--> sing-box SOCKS5 (DK, KZ, ...)

В QUIC: настоящий UDP приложений -> отдельный QUIC DATAGRAM, когда готов, иначе MBox STREAMS
В HTTPS: UDP приложений -> зашифрованный MBox STREAMS поверх внешнего TCP
TCP/управление: надёжные STREAMS при любом внешнем транспорте
```

**Входы и выходы:** QUIC и FastCGI — независимые *входные маршруты*, не отдельные страны. Origin аутентифицирует Noise и выбирает разрешённый локальный SOCKS5. Выход по умолчанию нужен beta.4.3/старым MBD1; beta.4.4 передаёт аутентифицированный `egress_id` в MBD2 для именованного выхода. Одна подписка может выдавать несколько стран; origin остаётся общей точкой отказа.

**AUTO транспорта** предпочитает QUIC и после отказа переходит на HTTPS с возможным разрывом активных потоков. **AUTO UDP** — другое: при готовом DATAGRAM и допустимом размере пакеты идут туда, иначе UDP-данные идут через надёжные STREAMS. OPEN/CLOSE UDP-ассоциаций и управление остаются надёжными. Отдельный DATAGRAM при простое может завершаться примерно за 30 секунд и подключается снова по реальному UDP-трафику с новым ключом/nonce-доменом AES-GCM для каждой эпохи. Постоянных PING нет; бесшовный multipath не реализован.

**Форматы Noise:** шифрование сессии и `record=v2` — не то же, что аутентифицированные поля OPEN `MBD1/MBD2`. `egress_id` не передаётся как недоверенный параметр HTTP и не позволяет запросить произвольный публичный SOCKS5: origin использует настроенный локальный allowlist.

**Безопасность и эксплуатация:** лимиты очередей, сессий и UDP, replay-защита, Android fail-closed. До гарантий отсутствия утечек нужны физический capture/Lockdown, длительный soak, сравнение батареи и нагрузочные тесты CPU FastCGI.
