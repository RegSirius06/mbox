# Безопасность

[English](../SECURITY.md)

MBox `1.0.0-beta.3` экспериментальный и не проходил независимый security audit. Строгий `cmac` защищает HTTP управляющие поля UP/DOWN/CLOSE при `auth.require_authenticated_control=true`: публичный beta.2.1 клиент с ним несовместим. Отсутствие DNS/TCP/UDP/IPv6 утечек ещё не доказано физическими packet captures.

- сессии используют `Noise_NKpsk0_25519_AESGCM_SHA256`;
- legacy crypto downgrade отсутствует;
- exact retry переиспользует исходный ciphertext, а не nonce;
- pre-auth OPEN ограничен по concurrent/rate;
- static server key загружается один раз и проверяются права;
- counter exhaustion fail-closed;
- Android `device_id` находится внутри аутентифицированного Noise OPEN;
- новая сессия supersede'ит stale-сессию только того же устройства;
- новые HTTPS provisioning links кладут секрет во fragment, а не query.

Секреты: `/etc/mbox/server.key`, users DB, backups, `mbox://` links. Не коммитьте их в Git.

Cronet уменьшает fingerprint Go TLS/HTTP, но не является security boundary и не гарантирует невидимость для DPI.

## Ресурсные лимиты Cronet-моста

Локальный HTTPS-мост доступен только на `127.0.0.1`, но другие приложения
на телефоне могут подключаться к этому порту без знания случайного токена.
Поэтому до аутентификации действует фиксированный лимит: не более 8 активных
обработчиков и 32 ожидающих подключений. Избыточные сокеты сразу закрываются,
а при остановке закрываются и необработанные соединения в очереди.
Проверка включает 1000 попыток переполнения и закрытие pending FD.

Это устраняет конкретную неограниченную очередь, но **не доказывает** общего
отсутствия утечек FD/памяти или обхода VPN. Перед релизом нужны испытания
Lockdown, захват трафика на физическом интерфейсе и длительный soak.
