# MBox QUIC: сертификат по доменному имени

**Статус:** патч для испытаний на базе `v1.0.0-beta.4.1`. На production не устанавливался. Старые профили с IP-сертификатом сохраняют совместимость; рабочий UDP 7443 до отдельного решения не трогаем.

## Один конфиг — все выдаваемые ссылки

Оператор один раз задаёт в `/etc/mbox/mbox.conf`:

```ini
[quic]
enabled = true
url = https://203.0.113.10:7444
server_name = node.example.com
ca_file =
```

Это **примеры**, не реальные адреса. `url` — числовой адрес и порт UDP-соединения; `server_name` — домен, проверяемый в TLS-сертификате (и передаваемый как SNI). Android по-прежнему не делает внешний DNS-запрос для защищённого QUIC-сокета. `ca_file` можно не задавать: тогда Go использует доступные системные корневые сертификаты. Однако **их наличие в Go-окружении конкретного Android нужно проверить**. При необходимости можно указать публичный долгоживущий корневой CA, но **не** постоянно обновляемый leaf-сертификат Caddy.

В тестовой версии `mboxctl` значения можно задать последовательно: `quic.url`, `quic.server_name`, затем `quic.enabled = true`. Изменение этих полей не перезапускает Noise-сервер. `mboxctl user link alice`, `user app-link` и `user qr` берут QUIC из общего конфига. Старые аргументы `--quic-url` и `--quic-ca-file` остаются, добавлен `--quic-server-name`.

Адрес и доменное имя продолжают входить в `mbox://`: клиент должен знать, куда подключаться, до первого соединения. Разница в том, что администратор теперь **не вводит их для каждого пользователя**. Ссылки пока статические. При будущей смене домена потребуется импорт новой ссылки либо отдельный защищённый механизм обновления подписок (не входит в патч).

## Что изменяется в клиенте

- Числовой IPv4 для QUIC и обязательная защита Android UDP-сокета остаются.
- Новое необязательное поле `quic_server_name` позволяет подключаться к IP и проверять DNS SAN в сертификате.
- Поле `quic_ca_pem` для нового доменного варианта необязательно. Для старого IP-варианта по-прежнему требуется.
- Проверка TLS остаётся обязательной. Неверное имя/сертификат не должны приводить к незащищённому соединению.
- Ранее импортированные профили сохраняют прежний формат.

## Caddy → QUIC: подготовленный, но не установленный механизм

`tools/quic-caddy-sync.sh` поддерживает:

- `--check`: только проверить соответствие открытого сертификата и ключа, DNS-имя, срок действия; никаких изменений.
- `--stage`: сделать защищённую версионированную копию в `/etc/mbox/quic-caddy/current`, **без перезапуска** службы.
- `--sync`: только после явной настройки systemd-службы на новое хранилище — переключить пару и перезапустить QUIC при изменении сертификата; при неудачном старте восстановить старую ссылку.

Подготовлены также `deploy/systemd/mbox-quic-caddy-sync.service` и `.timer`. **Ничего автоматически не устанавливается и таймер не включается.** Параметры окружения: `MBOX_CADDY_CERT`, `MBOX_CADDY_KEY`, `MBOX_QUIC_TLS_DOMAIN`, `MBOX_QUIC_TLS_STORE`, `MBOX_QUIC_UNIT`.

При внедрении через drop-in необходимо сохранить все четыре systemd credentials (пути, HMAC, сертификат и ключ):

```ini
[Service]
LoadCredential=
LoadCredential=paths:/etc/mbox/quic/paths.json
LoadCredential=hmac:/etc/mbox/origin-hmac.key
LoadCredential=cert:/etc/mbox/quic-caddy/current/server.crt
LoadCredential=key:/etc/mbox/quic-caddy/current/server.key
```

Вначале проверить **реальные пути и текущий unit**: очистка `LoadCredential=` удаляет прежние объявления; потеря `paths`/`hmac` отключит gateway. Не открывать Caddy-каталог ключей пользователю QUIC; использовать только root-копирование и systemd credentials. Состояние `active` после перезапуска не доказывает успешную TLS/Noise-сессию — нужна независимая проверка устройством.

## Приёмочные тесты и миграция

Проверить отдельный тестовый UDP-порт, не 7443: правильный DNS SAN, чужое имя, ошибочная цепочка CA, истечение, отсутствие доверенного корня, несовпадение ключа, QUIC→HTTPS fallback, выключение экрана, переключение сети. Сравнить новый Android с beta.4.1. Старый APK не умеет доменное TLS-имя для QUIC, поэтому менять сертификат на действующем UDP 7443 до перевода пользователей **нельзя**.

В дальнейшем при смене `.fun` на иной домен сначала выпустить и проверить новый сертификат, затем через защищённый канал выдать новые профили. Один зарегистрированный домен может содержать записи и для shared hosting, и для VPS. **Никаких гарантий доступности конкретной доменной зоны при фильтрации**, а также неподтверждённых регуляторных/тарифных утверждений в публичный гайд не включаем.
