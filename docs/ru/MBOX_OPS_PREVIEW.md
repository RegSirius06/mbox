# MBox beta.4.1 — безопасный операционный прототип

**Статус:** экспериментальный код для отдельной тестовой ветки, НЕ утверждён для prod. На текущий работающий VPS не разворачивать без отдельного решения. Не является RC1 и не создаёт GitHub release. Основа: коммит `0191357bf8e2c94b8aca397460aa0f32218aabc7`.

## Что было добавлено

- `install.sh`: `--check` (только чтение); сборка всех Go компонентов, включая `mbox-native-quic`; временная директория; SQLite online backup через `sqlite3.Connection.backup()`; резервная копия файлов; opt-in `--with-quic` для сервиса QUIC с существующим действующим сертификатом; opt-in `--with-admin` для локальной веб-панели. Инструмент и таймер перевыпуска сертификатов устанавливаются, но **таймер не включается**.
- `tools/mbox-admin/mbox_admin.py`: Python stdlib; HTTPS/QUIC не требует для административного интерфейса, т.к. HTTP доступен только через локальный root-owned Unix socket по SSH. SQLite используется исключительно для списка. Запись пользователей через whitelist команд `mboxctl`. Пароль scrypt, короткие сеансы и CSRF.
- `tools/mbox-admin/index.html`: без библиотек и CDN; список пользователей, создание, enable/disable, renew, limit, rotate, запрос приватного профиля.
- Отдельные systemd units для QUIC gateway и SSH-only Admin.

## Как посмотреть панель на тестовой VPS

Только после явного решения разворачивать экспериментальную ветку на **тестовой**, не работающей VPS:

```bash
# На тестовом Debian/Ubuntu VPS, после применения исходников:
./install.sh --check
./install.sh --with-admin

# На Arch (локальная машина оператора):
ssh -N -L 127.0.0.1:8765:/run/mbox-admin/admin.sock root@TEST_VPS
```

Откройте `http://127.0.0.1:8765` **на локальном компьютере**, введите пароль, созданный при установке. Панель **не открывает TCP-порт на VPS**, её Unix-сокет имеет mode 0600 под root. Не делайте публичное `ssh -R` или внешний проброс локального 8765. Не размещайте панель на общем хостинге.

При отсутствии готового Linux/VPS окружения локальные unit-тесты проверяют HTTP API и операции с поддельным `mboxctl` и временной SQLite. Это не тест работоспособности на реальном MBox сервере.

## Индивидуальные профили и подписки — важная разница

`mboxctl user link <id>` выдаёт статический приватный `mbox://`, содержащий PSK. В панели его можно получить явно. Он индивидуален, его можно отозвать/ротировать через `mboxctl`. **Это не динамический URL подписки:** пока нет публичного read-only provisioning endpoint, отдельного токена подписки и безопасной политики его ротации. Это следующий этап; нельзя использовать корневой административный socket как публичный subscription-сервер.

Если у оператора есть действующий CA для QUIC и публичный QUIC URL, их можно настроить **на тестовой машине** в `/etc/mbox-admin/admin.env` (root 0600), после чего перезапустить службу:

```ini
MBOX_ADMIN_QUIC_URL=https://203.0.113.10:7443
MBOX_ADMIN_QUIC_CA_FILE=/etc/mbox/quic/ca.crt
```

IP выше — документационный пример. Без этих настроек панель выдаёт **HTTPS-only** профили, как и `mboxctl user link` без явных опций. Не используйте случайный `ca.crt`: клиенты должны иметь доверие именно к сертификату обслуживающего QUIC gateway. Листинг и управление пользователями работают независимо от QUIC.

## QUIC сертификат

Установщик НЕ перевыпускает самоподписанный leaf и НЕ заменяет CA, так как старые клиенты могут доверять именно leaf. Он проверяет перед `--with-quic`, что файлы сертификата и ключа существуют, совпадают и сертификат не истекает в течение 7 дней. Он НЕ проверяет автоматически, что все реальные устройства доверяют новой цепочке или что внешний IP совпадает с SAN. Не включайте таймер до завершения миграции и полного теста старых клиентов.

Сначала на реально используемом VPS **только чтение**:

```bash
systemctl list-units --type=service --all | grep -Ei 'mbox|quic'
systemctl list-timers --all | grep -Ei 'quic|mbox'
# По systemctl cat <имя найденного unit> определить --cert/--key, затем:
openssl x509 -in /ПУТЬ/К/ТЕКУЩЕМУ/server.crt -noout -subject -issuer -dates -fingerprint -sha256
```

Не запускайте `quic-cert-renew.sh`, пока не определено, какой CA доверен пользователями. Публичные сертификаты можно показывать после удаления чувствительных адресов; приватные ключи и `mbox://` показывать нельзя.

## Проблема с переходом между приложениями

Сервер поддерживает несколько TCP streams внутри одной Noise-сессии. Отдельные TLS-соединения приложений — норма. Подозрение относится к reconnect, сетевым событиям, таймаутам и закрытию потоков, пока не проверено.

Воспроизвести на одном телефоне, одновременно сохраняя диагностические строки (перед публикацией удалить адреса, имена профилей и другие частные данные):

```bash
adb logcat -c
adb logcat -v time -s MBox:I MBox:W | grep -Ei 'NET |RECONNECT|RECOVER|CONNECTED|TUNNEL|QUIC|SOCKS|VERIFY'
```

На VPS выполнить **только чтение**:

```bash
mboxctl resources
ps -C mbox-server -C mbox-native-quic -C sing-box -o pid,comm,%cpu,rss,nlwp,etime
```

Проверьте последовательность: `CONNECTED` до перехода, события `NETWORK_CHANGED`/`RECONNECT`, смену QUIC→HTTPS, и повторную аутентификацию. При отсутствии таких событий исследовать сбои TCP/UDP и DNS независимо. Для 1% CPU нет доказательств высокой нагрузки — требуются данные в абсолютных единицах.

## Ограничения, которые ещё НЕ закрыты

- Нет полного чистого развёртывания `install.sh` на тестовой Debian/Ubuntu VPS; нет подтверждённой сборки quic-go с Go >=1.26 на этом раннере.
- Нет испытаний `--with-quic` с настоящим TLS, фронтендом REG.RU, Caddy/sing-box и обновлением профилей.
- Нет e2e тестов панели на реальном сервере с root `mboxctl` и состоянием SQLite после записей.
- Нет автоматического восстановления состояния при ошибке install; создаётся защищённая резервная копия, ручной rollback требуется отдельно. Установщик **может перезапускать production**, поэтому в текущем виде не запускать его на рабочем VPS.
- Нет ограничения трафика и IP; они требуют счётчиков/политик на origin и отдельного проекта.
- Нет публичных динамических URL подписки. Текущие ссылки — индивидуальные статические профили.
- Нет тестов физической утечки, долгого soak и fingerprint; относятся к RC1.

## Вопрос архитектуры репозиториев

Пока **оставить один репозиторий** для Go core, server, Android, native QUIC, systemd и тестов: общие типы и формат записи всё ещё тесно связаны, разделение увеличит release coordination. Admin достаточно держать под `tools/mbox-admin/` до стабилизации интерфейса; позже можно вынести в отдельный репозиторий, оставив серверный API и SQLite единственным источником истины.


## Безопасный установщик (обновление beta.4.2)

`./install.sh` без аргументов **не изменяет сервер**. `--check` — только проверка исходников и окружения. Действия явные и независимые:

- `--with-admin`: устанавливает веб-панель с Unix-сокетом и обновляет `mboxctl`, не перезапуская origin и оба QUIC-шлюза. Первый запуск запрашивает пароль администратора. Веб-панель доступна только через SSH-перенаправление `root@VPS`.
- `--upgrade-origin`: обновляет именно origin и его вспомогательные бинарники; **перезапускает** `mbox-server` и может прервать существующие сессии. Использовать только при плановом обновлении после проверки резервной копии. Резервные данные сохраняются в `/root/mbox-preinstall-*`. Откат при ошибке выполняет оператор вручную, копию живой SQLite не восстанавливают поверх действующего сервиса.
- `--fresh-install`: только на ещё не настроенной машине; отказывается менять уже установленный MBox.
- `--with-quic`: намеренно **не поддерживается** этим установщиком на стадии preview, поскольку QUIC на 7443/7444 работает в выделенных systemd-службах с `LoadCredential`. Не подменять их конкурирующей службой. Для продления Caddy используется отдельный `quic-caddy-sync.sh`.

Запуск `--with-admin` на существующей VPS не устанавливает QUIC, не меняет TLS, не синхронизирует REG.RU. Саму админ-панель необходимо дополнительно испытать на реальных операциях прежде, чем полагаться на неё как на production интерфейс.
