## Что существует сейчас

- **Android arm64:** интегрированный клиент на `VpnService`/TUN работает и испытывался в ветке beta 4. Native QUIC пока включён только в debug-вариант; для релиза его нужно интегрировать в release.
- **Linux:** сервер, FastCGI relay и части Go-клиента существуют, но **готового официального системного VPN-клиента для рабочего стола нет**.
- **Windows / macOS / iOS:** готового поддерживаемого клиентского приложения пока нет.

Нативный QUIC поверх UDP делает MBox потенциально полезным не только при ограничениях мобильной сети: его можно применять как обычный внешний транспорт VPN в сетях, где UDP доступен. Но **APK нельзя просто перекомпилировать под Windows/Linux**: часть системы завязана на Android.

## Минимальный план разработки

1. **Не переписывать протокол:** сохранить существующие Go-ядро, Noise, MBox framing, flow control, UDP-forwarding и QUIC gateway.
2. Выделить тонкий платформенный слой для TUN, маршрутов/DNS и управления транспортом. Учитывать реальные границы нынешних процессов.
3. **Сначала Linux:** TUN, маршрутизация, DNS, простой CLI, вручную HTTPS/QUIC; затем проверка завершения процесса и сетевых утечек.
4. **Потом Windows:** подходящий поддерживаемый TUN-драйвер/интеграция, маршруты, DNS, особенности подписания дистрибутива.
5. **macOS/iOS позже:** отдельно изучить разрешения Network Extension и требования распространения.
6. На каждой платформе отдельно проверить Auto, fail-closed и DNS/IPv6. Android `VpnService.protect()` и интеграция Cronet автоматически не переносятся.

Это **roadmap, а не обещание сроков**. Pull Request для других платформ приветствуются, особенно если используют имеющееся ядро и сопровождаются тестами.
