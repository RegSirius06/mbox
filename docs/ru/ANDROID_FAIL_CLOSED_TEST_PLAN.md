# Проверка VPN fail-closed на Android — beta.4.1

[English](../ANDROID_FAIL_CLOSED_TEST_PLAN.md) · [Статус](BETA4_1_STATUS.md)

**P0: ожидает физических испытаний.** Android `VpnService` и полный TUN-маршрут — не замена системному Lockdown после полной смерти сервиса. Не заявляйте «нулевые утечки», пока независимый packet capture не подтвердил IPv4, IPv6, DNS, TCP, UDP на Wi-Fi и мобильной сети.

## Сценарии

1. QUIC подключён → блокировка UDP; проверить RECOVERING и отсутствие прямой отправки пакетов приложений.
2. QUIC в Auto → блокировка UDP при доступном HTTPS; подтвердить HTTPS fallback, затем восстановление доступности QUIC.
3. Ручной HTTPS → недоступен REG.RU frontend; проверить fail-closed без переключения в QUIC.
4. Wi-Fi выключен, Wi-Fi→LTE→Wi-Fi, авиарежим, принудительный Doze, выход из Doze.
5. Принудительная остановка Go core, QUIC gateway и HEV по отдельности; процесс жив, но застрял.
6. Пользователь останавливает VPN во время восстановления; отдельно — отзыв разрешения VPN и системное уничтожение процесса.
7. Проверить с Always-on off, Always-on on и Android Lockdown on; записать поведение каждого режима и возможные периоды без VPN.
8. Во всех случаях захватывать трафик с роутера/физического интерфейса и фиксировать только обезличенные итоги. Не публиковать `mbox://`, PSK, ключи, полный raw capture.

Для подготовки и автоматических тестов см. [TESTING.md](TESTING.md). В приложении без Lockdown нельзя гарантировать сетевую блокировку после полного завершения VPN-сервиса.
