# MBox beta 4 — полевые испытания, диагностика и риски

[English](../BETA_4_FIELD_TESTING.md)

## Почему нужны реальные пользователи

Некоторые ошибки зависят от белых списков конкретного оператора, переходов Wi-Fi/LTE/5G, политики shared hosting, возраста процессов FastCGI, особенностей буферизации посредника, NAT, версии Android и маршрутизации. Все сочетания невозможно воспроизвести локальным моделированием. Чем больше добровольных тестировщиков, тем выше шанс обнаружить редкие сбои; **это не гарантирует ни нахождения всех багов, ни отсутствия утечек**.

## Что уже наблюдали к 13.11.2026

- На Android вручную работают HTTPS и прямой native QUIC.
- Auto при смене Wi-Fi на ограниченную мобильную сеть переходил после отказа QUIC на HTTPS; при возвращении на Wi-Fi наблюдалось соединение по QUIC.
- Разработчик сообщил о работоспособности HTTPS-маршрута на **МегаФоне** в условиях ограниченной сети. Это **один успешный полевой тест**, а не обещание поддержки всех регионов и тарифов.
- После снижения привилегий QUIC gateway Android успешно прошёл QUIC handshake, Noise handshake и установил туннель.
- Локальные проверки: Go tests/race/vet без ошибок, **96 Python-тестов пройдены**, source-layout OK, **debug APK** успешно собран. Равнозначность будущей release-сборки ещё не доказана.

## Необъяснённый сбой FastCGI 12.11.2026

HTTPS-фронтенд на shared hosting возвращал HTTP 500. Apache `mod_fcgid` сообщал о сбросах соединений и отсутствии заголовков FastCGI. Прямой контрольный запрос к обработчику FastCGI работал. Завершение и повторный запуск принадлежащих аккаунту процессов `relay.fcgi` восстановили HTTPS. **Первопричина не установлена**. Длительная работа, cover, обработка запросов и особенности хостинга — пока только гипотезы. Не следует считать, что автоматическое восстановление уже реализовано. Ответ 404 на обычный путь в `mboxctl relay test` сам по себе не означает поломки: фронтенд может намеренно скрывать служебные маршруты.

## Приёмочные проверки

1. HTTPS и QUIC: новая Noise-сессия и передача обычного TCP.
2. UDP-over-HTTPS: контрольный STUN через VPN.
3. Auto: fallback при недоступном QUIC до старта и после обрыва установленной сессии.
4. Fail-closed: включить Always-on VPN и «Блокировать подключения без VPN», аварийно завершить приложение и проверить новые соединения. Такой тест **не заменяет** анализ трафика на физическом интерфейсе.
5. При сбое записать версию Android/MBox, оператора, Wi-Fi/LTE/5G, роуминг, режим транспорта, время **с часовым поясом** и очищенные диагностические стадии.
6. При HTTP 500 собрать код ответа, состояние FastCGI-процессов и **новые** записи журнала Apache, без публикации секретных URL/путей.

## Как сообщить об ошибке

Откройте [GitHub Issues](https://github.com/RegSirius06/mbox/issues) и используйте шаблон **Bug report**. Сначала проверьте существующие Issues. Укажите шаги воспроизведения, ожидаемый и фактический результат, сеть, режим транспорта, состояние Lockdown и время с часовым поясом.

**Нельзя публиковать:** полные ссылки `mbox://`, PSK, пароли, HMAC-секреты, приватные ключи, закрытые пути и URL фронтенда, необработанный logcat, пользовательскую базу и содержимое трафика. Для потенциальной уязвимости не выкладывайте публичный PoC с секретами: проверьте, доступен ли в репозитории приватный GitHub Security Advisory.

Предложения и патчи приветствуются в виде форка и Pull Request; включение изменений зависит от ревью. См. [CONTRIBUTING.ru.md](../../CONTRIBUTING.ru.md).
