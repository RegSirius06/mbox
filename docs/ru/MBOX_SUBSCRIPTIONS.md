# Подписки MBox — beta.4.2

## Архитектура

`https://DOMAIN/<настроенный-путь>/<token>` — постоянный адрес. Токен 256 бит: в SQLite хранится **только SHA-256**, не сам токен. Публичный endpoint отвечает JSON v1 с несколькими действующими **обычными** `mbox://`-профилями. Каждый профиль использует одну и ту же пару Noise/PSK, camouflage и QUIC, но свой HTTPS ingress (REG.RU, Beget и т. д.). Адрес подписки не меняется при смене endpoint, PSK и TLS-сертификата; старая ссылка блокируется при отзыве токена, отключении/удалении пользователя либо истечении срока. Ключ пользователя не дублируется в отдельном файле.

**Две точки входа ≠ два независимых origin.** Оба shared-хостинга маршрутизируют на один MBox origin, значит отказ origin всё равно общий. Beget необходимо отдельно проверить на корректную работу FastCGI-моста, совместимость путей, таймауты и квоты; работа REG.RU не гарантирует работу Beget.

## Постоянные ссылки и отзыв

Кнопка **«Показать подписку»** идемпотентна: при первом нажатии создаёт одну основную ссылку пользователя, а при следующих показывает **точно тот же токен**. Публичный путь подставляется динамически из `[subscription] public_url`. Если изменить путь, старые ссылки с прежним путём перестанут открываться — пользователям надо отправить новый URL с тем же токеном.

Ссылки, выпущенные старым алгоритмом, **остаются рабочими** и не отзываются автоматически. Восстановить их исходный URL из SHA-256 невозможно. Панель показывает количество активных ссылок. «Отозвать подписки» отключает **все** токены этого пользователя, включая старые; следующее нажатие создаст новую основную ссылку. Триггер SQLite автоматически отзывает ссылки при удалении пользователя, даже если удалить его через CLI, поэтому повторное создание такого же ID не возобновит старый доступ.

Отдельный секрет `/etc/mbox/subscription-link.key` (0600, 32 байта) создаётся при первой основной подписке. **Обязательно хранить в резервной копии вместе с `users.db`.** `mboxctl backup create` сохраняет `/etc/mbox` и БД. Если ключ утерян, отображение старых основных ссылок блокируется вместо их скрытого перевыпуска; публичная выдача по их хешу продолжает работать. Никогда не публикуйте токены, ключ и PSK.

## Установка без изменения production VPN

1. На Arch примените патч и выполните тесты. На VPS перенесите текущие исходники, включая файлы `tools/mbox-subscription/mbox_subscription.py` и `deploy/systemd/mbox-subscription.service`.
2. На VPS `./install.sh --check`, затем `./install.sh --with-subscriptions`. Это установит HTTPS upstream на `127.0.0.1:18450`, обновит панель, **не** перезапустит origin, QUIC или Caddy. До отдельной настройки Caddy подписки недоступны снаружи.
3. Попробуйте безопасный автоматический Caddyfile-патч (работает только с простым отдельным блоком домена; сложную конфигурацию оставит без изменений):

   ```bash
   python3 tools/mbox-subscription/caddy_route.py --check
   python3 tools/mbox-subscription/caddy_route.py --apply
   ```

   Если `--check` отказал, в существующий HTTPS vhost Caddy добавьте **до catch-all правил** (пример именно для Caddyfile, адаптируйте существующую конфигурацию):

   ```caddyfile
   handle /mbox/sub/* {
       log_skip
       reverse_proxy 127.0.0.1:18450
   }
   ```

   Не используйте `handle_path`, иначе префикс `/mbox/sub/` будет удалён. Исключите полный URL с токеном из access-логов Caddy или редактируйте его. Сначала `caddy validate --config /etc/caddy/Caddyfile`, затем только `systemctl reload caddy`. Если используется JSON-конфигурация/Caddy API, добавляйте эквивалентный маршрут там, а не перезаписывайте конфиг.
4. Проверьте локальный upstream без токена: `curl -i http://127.0.0.1:18450/mbox/sub/invalid` — ожидается 404. После Caddy проверьте `curl -i https://DOMAIN/mbox/sub/invalid` — также 404, а HTTPS/TLS нормально работает.
5. В панели «Показать подписку» возвращает одну и ту же HTTPS-ссылку при повторном нажатии; «Отозвать подписки» аннулирует **все** токены конкретного пользователя. Адрес ссылок подставляется из `[subscription] public_url` или автоматически: `[quic] server_name`, иначе домен `[server] public_url`. Для переопределения добавьте `[subscription] public_url = https://DOMAIN/mbox/sub` в `mbox.conf`.

## Точки входа

По умолчанию один профиль с `server.public_url`. Добавление второго URL через панель создаёт `subscription-endpoints.json` (0600) и определяет набор профилей для **всех** подписок. Публичный домен предпочтительнее IP, когда он доступен. Для каждого ingress указывайте полный HTTPS `transport.url`, включая base path. Разные ingress предполагают одинаковые camouflage-пути и одинаковый backend. Перед переключением клиента всегда проверяйте реальную доступность нового ingress.

## Android

Импорт обычного `mbox://` не меняется. HTTPS URL подписки принимает новая версия Android, шифрует URL и кэш профилей через Android Keystore, позволяет выбрать ingress в Settings. При открытии приложения с отключённым VPN пытается обновить подписку, но при ошибке оставляет ранее импортированный конфиг. При активном VPN автообновление не выполняется, чтобы не нарушить fail-closed поведение. По сроку и сессиям пока доступны только реально известные серверу поля; квоты трафика и зарегистрированных устройств не придуманы.

## Что НЕ входит в этот этап

Строгая привязка к устройству (с долговременной регистрацией и доказательством владения ключом), учёт трафика, отдельные визуальные формы для **всех** редких `mboxctl` команд и автоматическое переключение между двумя HTTPS ingress во время активного туннеля. Нужны отдельные изменения origin, длительные интеграционные испытания и защита от обхода через старый клиент. Здесь реализованы выдача/отзыв подписок, набор ingress, выбор и обновление Android, безопасные CLI операции через панель, групповое удаление.

## Управление через браузер и аварийный CLI

Повседневные настройки доступны формами и кнопками SSH-only панели. При недоступности панели сохраняется аварийное администрирование `mboxctl` по SSH; произвольный CLI и shell через браузер не предоставляются. QR формируется `qrencode` на VPS.
