# Android: несколько подписок и точек входа (beta.4.2)

Новая версия хранит **до 12 независимых HTTPS-подписок**, в каждой — **от 1 до 12 MBox-профилей** (например, REG.RU и Beget). Формат `mbox://`, Noise и протокол MBox не меняются.

## Использование

В приложении открой **Settings → Add HTTPS subscription** и вставь ссылку вроде `https://your-host/api/v2/<token>`. Приложение скачает JSON `version=1`, проверит каждый `profiles[].link` как обычный MBox-профиль и подключит первый вход. В **Settings → Subscriptions** можно выбрать подписку, выбрать точку входа, обновить одну подписку или удалить её локальную копию. **Refresh all subscriptions** обновляет записи по очереди: неудачное обновление оставляет прежний кэш доступным. Смена публичного Noise-ключа не принимается без ручного переимпорта.

URL, JSON подписок и PSK защищены AES-GCM через Android Keystore. В обычных настройках Android хранятся только случайные ID и ID выбранного входа. Прежняя единственная подписка распознаётся как `legacy`: она не удаляется и не мигрирует при обновлении. Новые находятся во внутреннем каталоге приложения `subscriptions/items/<id>/`.

Прямой `mbox://` остаётся доступен. **Повторно импортированный в новой APK** прямой профиль сохраняется зашифрованно и затем выбирается через **Use direct profile**. Старый прямой профиль продолжит работать после обновления APK, но для возможности переключаться обратно на него после выбора подписки исходную ссылку надо импортировать один раз в новой версии. Сохрани старую ссылку! Переключение профилей возможно только при выключенном VPN.

**Удаление подписки на телефоне не отзывает токен сервера.** Отзыв выполняется в веб-панели. Если администратор меняет путь `/api/v2`, ранее выданные URL перестают открываться, пока пользователь не обновит ссылку.

## Проверки на Arch

```sh
cd ~/src/mbox-main
python3 -m pytest -q tests
GO111MODULE=off go test ./server ./client
(cd android && ./gradlew :app:assembleDebug)
```

Релизная APK должна иметь **тот же сертификат подписи**, что установленная у пользователей. Debug-APK с другой подписью не обновит существующую release-APK поверх неё; переустановка может удалить данные приложения. До распространения проверить fingerprint подписи и package ID.

## Что проверяем на телефоне

1. Обновить APK **без удаления**; старый профиль подключается по QUIC/HTTPS.
2. Импортировать две подписки и проверить сохранение после перезапуска приложения.
3. Добавить в одну подписку два входа, обновить, выбрать каждый и проверить подключение.
4. Обновить одну подписку без потери второй; при отсутствии сети должны остаться кэшированные профили.
5. Сохранить прямой `mbox://` новой APK, перейти на подписку и затем вернуться к прямому профилю.
6. Проверить ошибки JSON, 30x, неверный Noise-сервер, дубли точек входа и слишком большие ответы.
7. Проверить переход Wi-Fi ↔ мобильная сеть, простой с выключенным экраном и fail-closed.

## QR-код веб-панели

На VPS должна быть программа **`qrencode`**. Для диагностики запусти `tools/mbox-admin/qr-preflight.sh` на VPS. Если программы нет — установить `qrencode` пакетным менеджером. Для слишком длинного прямого `mbox://` с сертификатом QR физически может не поместиться; в таком случае используй более короткую HTTPS-подписку. Не отправляй ссылку-токен в общедоступные отчёты об ошибках.

## Сверка исходников VPS → Arch

Запусти на Arch `tools/mbox-audit-vps.sh ~/src/mbox-main root@YOUR_VPS_IP`. Скрипт забирает только установленные исходники панели и подписок, отдельно сохраняет локальный снимок Caddy/systemd вне Git, затем пишет `MATCH` / `DIFF` / `ONLY_VPS`. **Ничего на Arch автоматически не перезаписывает**. Проверяй изменения перед слиянием. Запрещено выкладывать в Git `/etc/mbox`, `users.db`, TLS-ключи, пароли и PSK.
