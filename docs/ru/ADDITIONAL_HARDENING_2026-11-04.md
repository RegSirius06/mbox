# Дополнительное усиление безопасности MBox — 4 ноября 2026 года

Этот набор коммитов дополняет beta.2.1 и предыдущий P0/P1 hardening. **Это не подтверждение полной готовности к production.**

## Защита логов

Стандартный Go-логгер вырезает целиком URL `http(s)://` и `mbox://`, а также значения PSK, паролей, токенов, private_key и Basic/Bearer credentials. Длина одной записи ограничена, переносы строк экранируются. В Android аналогичная обработка применяется к выводу Go-core, исключениям Cronet и сообщению о повторном подключении. Есть регрессионные тесты Go и Java.

Ограничение: сторонние библиотеки, прямой `fmt.Print` и прежние логи не очищаются автоматически. Секретные provisioning-ссылки и raw-конфиги публиковать нельзя.

## Код завершения 141

Код 141 соответствует `SIGPIPE`. При закрытии Android-частью pipe чтения логов запись core в stdout/stderr потенциально могла приводить к `SIGPIPE`. Теперь Go-клиент игнорирует этот сигнал и получает обычный `EPIPE`. Регрессионный тест намеренно закрывает stdout подпроцесса. **Это не доказывает, что именно этот механизм был причиной всех наблюдавшихся реконнектов:** переключения Wi-Fi/LTE и airplane mode нужно проверить на телефоне.

## Проверка APK

`tools/check-production-apk.sh` проверяет криптографическую подпись через Android SDK `apksigner`, отсекает стандартный debug-сертификат, `android:debuggable=true` и неверный package ID. Скрипт печатает SHA-256. Он предназначен для будущих production-подписанных APK, а не для обычного debug APK во время разработки.

Для полноценной политики подписания дополнительно требуется pin ожидаемого сертификата и release provenance/SBOM.

## Что ещё не закрыто

Android lockdown/fail-closed и packet-capture приёмка; native UDP через Noise; одноразовый подписанный provisioning; новый протокол для асимметричной аутентификации; воспроизводимые зависимости/подписи/SBOM; нагрузочные и длительные soak-тесты.

## Порядок установки

1. Сначала на Arch создать чистую ветку и применить **предыдущую** серию hardening.
2. Затем добавить эту дополнительную серию, проверить `go test`, `go test -race`, `go vet`, Python и Android build.
3. Провести тесты на Android (Wi-Fi, мобильные операторы, airplane mode, блокировка трафика при сбое).
4. Только после этого поэтапно обновлять REG.RU relay и RU origin, сохраняя рабочий rollback. Не включать relay-origin HMAC только на одной стороне.
