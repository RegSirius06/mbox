# MBox beta.4.4 — мониторинг REG.RU

Предварительная интеграция: фиксированная SSH-команда, один сеанс сбора по запросу, 5/15/30/60 минут, интервал 5/10/30 секунд. CPU FastCGI — процент одного ядра, нижняя оценка по приращению utime+stime совпадающих PID и starttime. Первое измерение CPU отсутствует; RSS суммируется (общие страницы учитываются повторно). Слоты — наблюдаемые записи FLOCK /proc/locks, не тарифные метрики. В случае недоступности /proc/locks значение отсутствует. Сбор может продолжаться при закрытой вкладке до таймера; Stop закрывает SSH, удалённый процесс обнаруживает разрыв при следующей записи либо завершается по alarm. Один результат в RAM, CSV перед новым измерением; перезапуск панели удаляет результат.

На Arch: `python3 apply.py ~/src/mbox-main`. Прогон `python3 -m pytest -q tests/test_beta44_monitor.py` из checkout. На VPS из переданного каталога `python3 setup-relay-monitor.py`, затем `bash deploy-monitor-admin.sh`. Настройка использует сохранённый `/etc/mbox/relay-deploy.json` и известный ключ хоста из `/root/.ssh/known_hosts`; если его нет, остановится. Пароль SSH вводится только при установке. Секреты не помещаются в git. Отдельный закрытый ключ без парольной фразы хранится в root-only `/etc/mbox-admin/relay-monitor/`; удалённый `authorized_keys` ограничивает выполнение фиксированного sampler и запрещает forwarding/PTY. Setup проверяет снимок и отказ выполнения `true`. Если проверка не прошла, удалить только строку с комментарием `mbox-relay-monitor` из `~/.ssh/authorized_keys` на REG.RU; не удалять другие ключи. Для полного отзыва удалить эту строку и закрытый ключ на VPS. Деплой обновляет только admin Python/HTML, перезапускает только mbox-admin, откатывает файлы при неуспешной HTTP-проверке. Не меняет FastCGI, origin, VPN-профили или пароли.

Не реализованы: тарифный CPU всего аккаунта, история ошибок HTTP и origin-метрики, постоянная история, подключение нескольких хостингов. Полные тесты репозитория, реальный SSH и браузерные испытания необходимы на целевых системах.
