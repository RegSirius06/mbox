**Актуально для production beta.4.4:** origin с rekey, gateway и DATAGRAM Unix socket/ACL устанавливаются отдельно. Назначение страны через `egress_id` требует локального разрешённого SOCKS5 и доступного для пользователя `mbox` файла `egress.json` (`root:mbox 0640`). Изменения в панели не переносят автоматически бинарник origin. `bash install.sh --check` ничего не изменяет; полный upgrade/rollback тестируйте на staging. CPU/воркеры REG.RU остаются критическим эксплуатационным риском.

# beta.4.4: диагностика эксплуатации по запросу

Эти команды работают только по запросу. Они не перезапускают сервисы, не меняют конфигурацию, не убивают workers и не открывают публичный административный интерфейс. Исключение — ограниченные HTTP-запросы команды `relay bench`.

## Снимок REG.RU

Запускать на origin VPS от root:

```sh
mboxctl relay stats
```

Команда использует сохранённый SSH-профиль деплоя и один раз собирает снимок на REG.RU. Она показывает лимит слотов, существующие lock-файлы, активные `flock`-блокировки (если доступен `/proc/locks`), PID процессов `relay.fcgi`, время жизни, накопленное CPU time и RSS. Постоянного опроса нет. `CPU_TIME` — накопленное процессорное время, а не мгновенный процент CPU. Если хостинг скрывает `/proc/locks` или аргументы процессов, значение обозначается как неизвестное, а не придумывается.

## Ограниченная проверка relay

```sh
mboxctl relay bench --confirm --requests 40 --concurrency 2
```

Команда отправляет конечное число `GET`-запросов на настроенный публичный endpoint `/health`. Этот путь явно разрешён relay и не создаёт пользовательскую сессию, не передаёт профиль, PSK, токен или пользовательские данные. Количество запросов ограничено 500, скорость отправки — 20 запросами/с (по умолчанию 4), параллелизм — удвоенным лимитом слотов (но не более 16), каждый запрос имеет ограниченный таймаут. Выводятся HTTP-коды, пропускная способность и p50/p95/p99 задержки. Это контролируемое приёмочное испытание, а не DDoS-бомбер и не замена реальному VPN-трафику с нескольких устройств.

Снимите `mboxctl relay stats` до и после теста. Сравните активные слоты, RSS workers и накопленное CPU time. Для процента CPU shared hosting авторитетны графики ISPmanager: эта команда не пытается вычислять его по косвенным данным.

## Backend Web Admin

```sh
mboxctl admin status
```

Команда проверяет `mbox-admin.service`, приватный Unix-сокет и локальный HTTP 200 через этот сокет. Она не открывает TCP-порт и не меняет SSH-only политику доступа. На рабочем компьютере создайте существующий SSH-туннель:

```sh
ssh -N -L 8765:/run/mbox-admin/admin.sock root@<VPS_HOST>
```

После этого откройте `http://127.0.0.1:8765/`. Исправный локальный backend сам по себе ещё не доказывает, что SSH-туннель и браузер настроены правильно.

## Таймаут FastCGI

Теперь watchdog на 45 секунд охватывает весь прикладной обработчик, а не только upstream proxy: чтение тела, проверку, получение слота и proxy. Таймаут бездействия чтения 40 секунд по-прежнему ограничивает полное молчание до и во время разбора FastCGI-запроса. Срабатывание watchdog может прервать другие запросы в том же worker; необходимо проверить модель REG.RU и удерживать штатные запросы в пределах 45 секунд. Cron для периодического kill или recycle workers не устанавливается.
