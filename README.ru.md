# MBox

[English](README.md) · [Android](docs/ru/ANDROID_BETA4_1.md) · [Безопасность](docs/ru/SECURITY.md) · [История изменений](CHANGELOG.ru.md) · [Примечания к релизу](RELEASE_NOTES.ru.md)

**Актуальный кандидат: `1.0.0-beta.4.1`** — Android 10+ / ARM64 / `io.mbox.android`. MBox — экспериментальный шифрованный VPN-клиент, а не независимо аудированный продукт с гарантированным обходом любой фильтрации. Публикация релиза и проверка финального APK с production-подписью — отдельные действия.

## Подключение

1. Скачайте **подписанный существующим production-ключом** `MBox-1.0.0-beta.4.1-android-arm64.apk` с [GitHub Releases](https://github.com/RegSirius06/mbox/releases) **после публикации prerelease**. Сверьте фактический SHA-256 файла и отпечаток сертификата подписи с release notes.
2. Импортируйте личный профиль `mbox://` в настройках. Никогда не прикладывайте эту ссылку к issue: в ней долговременные секреты доступа.
3. Нажмите **Connect**. В публичном APK транспорт выбирается автоматически: QUIC с переходом на HTTPS при сбое, если оба маршрута настроены. Профили только с HTTPS продолжат работать через HTTPS. Ручной выбор доступен только в debug-сборке. Интерфейс показывает этапы подключения, активный транспорт, проверку Noise и восстановление.

## Транспорты и восстановление

```text
Android VpnService / TUN / HEV -> Go core MBox / аутентифицированный Noise
                               +-- QUIC/HTTP3/UDP -> прямой gateway VPS -> origin MBox
                               +-- HTTPS/HTTP2/TCP -> Cronet -> опционально REG.RU FastCGI -> origin MBox
```

- **QUIC:** прямой UDP к VPS из профиля. UDP приложений передаётся внутри надёжных HTTP/3 **streams**, а не QUIC DATAGRAM.
- **HTTPS:** Cronet HTTP/2 поверх TLS/TCP через настроенный endpoint, в том числе shared hosting/FastCGI. UDP приложений инкапсулируется в MBox-записи **поверх TCP**.
- **Auto:** предпочитает QUIC при подключении, после подтверждённого отказа переходит на HTTPS. Это не multipath и не бесшовная миграция потоков: старые соединения могут оборваться. Постоянная безопасная фоновая проверка возврата на QUIC при рабочем HTTPS не обещается.
- **Контроль соединения:** перед CONNECTED требуется аутентифицированный Noise ping/pong. Go core проверяет удалённую сессию каждые 30 с при активности и 90 с при простое (с jitter); после выхода из Doze запрашивается внеочередная проверка. QUIC gateway и HEV также контролируются.

## Безопасность и уровень проверки

Разработчик сообщил об успешной проверке подключения, простоя с выключенным экраном, Wi-Fi/мобильной сети, полной потери сети и Auto на сборке beta.4.1. На Arch прошли Go client/server и native QUIC race-тесты; собран debug APK. **Это не подтверждает все те же сценарии на финальном production-signed APK** и не устанавливает физическую причину исходного зависания.

**P0 пока не закрыт:** независимый захват IPv4/IPv6/DNS/TCP/UDP с физического интерфейса, Android Lockdown, принудительная остановка gateway, длительный soak и полная приёмка подписанного APK ожидаются. Always-on помогает восстановлению VPN; **Android Lockdown** нужен для системной блокировки обхода, если VPN-сервис полностью исчез. Гарантий полного отсутствия утечек, идентичности браузеру и прохождения любого DPI нет.

Тестовый QUIC-сертификат оператора истекает **7 декабря 2026 года**. Инструменты ротации подготовлены, **но не установлены на VPS**. Для миграции с доверия к старому самоподписанному leaf на новый CA может понадобиться однократный аутентифицированный импорт профиля. TLS-проверку не отключать.
