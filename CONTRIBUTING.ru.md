# Как помочь разработке MBox

[English](CONTRIBUTING.md)

MBox — экспериментальное сетевое ПО. Приветствуются баг-репорты, небольшие исправления, улучшения документации и эксперименты с другими платформами. Автор может принять, предложить изменить или отклонить PR; отправка изменений не гарантирует их слияния.

## Сообщить об ошибке

Откройте [GitHub Issues](https://github.com/RegSirius06/mbox/issues), выбрав **Bug report**. Сначала проверьте уже созданные Issues. Укажите шаги воспроизведения, ожидаемый и фактический результат, версии Android/MBox, HTTPS/QUIC/Auto, Wi-Fi/LTE/оператора/роуминг, наличие белых списков, время и часовой пояс, а также очищенный лог. **Редкую ошибку тоже стоит прислать**, даже если пока нельзя стабильно её воспроизвести.

**Не публикуйте секреты:** полные `mbox://` ссылки, пароли, PSK, HMAC-ключи, приватные ключи, заголовки авторизации, закрытые пути веб-фронтенда, базы пользователей или сырой logcat. При подозрении на эксплуатируемую уязвимость сначала проверьте возможность приватного security report на GitHub.

## Предложить исправление через PR

1. Сделайте fork и отдельную ветку. Предпочитайте минимальное исправление с переиспользованием существующего Go-кода, без лишних абстракций.
2. К исправлению ошибки приложите регрессионный тест. Для сетевого кода важны отказ, отмена операций и освобождение ресурсов.
3. Запустите необходимые Go-тесты (по возможности с `-race`), Python и Android-проверки. Не заявляйте о непроведённых испытаниях.
4. При изменении поведения обновите документацию по-русски и по-английски. Не вставляйте реальные адреса серверов, секреты и конфигурации в тесты.
5. Создайте Pull Request: проблема, решение, результаты тестов, риски и требования к платформе. Если есть Issue, укажите ссылку.

Для Linux/Windows и других систем см. [roadmap](docs/ru/PLATFORM_ROADMAP.md). Go-ядро QUIC можно переиспользовать, но интеграция системного VPN на каждой ОС должна разрабатываться и тестироваться отдельно.
